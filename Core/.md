# 核心 (Core) 目录

## 职责

`Core` 目录是整个框架的基石。它包含了所有通用的、可重用的、与具体游戏内容（如特定的Boss、物品）无关的底层系统。这里的代码是整个Mod的技术核心。

## 设计原则

- **内容无关 (Content Agnostic)**: `Core` 中的代码不应知道任何关于 `Content` 目录中的具体实现。例如，`MovementSystem` 只处理 `MovementComponent`，它不关心这个组件是属于哪个Boss。
- **抽象化 (Abstraction)**: 提供接口和基类来定义核心概念（如 `IComponent`, `ISystem`, `IState`），使得上层逻辑可以依赖于这些抽象，而不是具体的实现。
- **可重用性 (Reusability)**: `Core` 中的任何系统（如事件总线、网络管理器）都应该能被未来开发的任何新内容直接使用，无需修改。

## 子目录结构

- **`/Builders`**: 包含用于构建复杂对象的“构建器”类。例如，`EcsBoss` 作为所有ECS管理的NPC的基类，简化了它们的创建流程。
- **`/Configuration`**: 负责从外部文件（如 `.hjson`）加载配置，使得游戏参数可以被设计师在不修改代码的情况下调整。
- **`/ECS`**: 整个**实体-组件-系统 (Entity-Component-System)** 架构的核心。这是游戏逻辑和数据分离的实现地。
- **`/Events`**: 实现了一个全局的**事件总线 (EventBus)**，用于在框架的不同部分之间进行解耦的通信。
- **`/Networking`**: 包含了新的网络管理器，负责在多人游戏中高效、可靠地同步数据。
- **`/Stats`**: 提供了一套可修改的属性系统，用于动态地计算和调整如伤害、防御等数值。
