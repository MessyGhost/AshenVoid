# 有限状态机 (Finite State Machine) 目录

## 职责

本目录实现了一个有限状态机（FSM），用于管理NPC（尤其是Boss）的**宏观、高阶状态**。它决定了Boss在某个时刻应该处于哪个大的行为模式或战斗阶段。

例如，一个Boss的生命周期可以被划分为以下几个状态：
- `SpawnState` (出生状态)
- `Phase1State` (一阶段)
- `Phase2State` (二阶段)
- `DeathState` (死亡状态)

FSM负责在这些宏观状态之间进行切换。

## 核心概念与文件

- **`IState.cs`**: 定义了所有状态类的契约（接口）。一个状态的核心职责包括：
    - `Enter()`: 当进入该状态时执行一次的逻辑（如播放音效、改变移动参数）。
    - `Exit()`: 当离开该状态时执行一次的逻辑（如清理数据）。
    - `Update()`: 在该状态下每帧执行的逻辑。
    - `CheckTransitions()`: 每帧检查是否满足切换到其他状态的条件（如HP低于50%则切换到二阶段）。

- **`StateFactory.cs`**: 一个简单的工厂类，用于创建和管理状态的实例。

- **`AIStateComponent.cs`**: 这是一个组件，它将FSM的功能赋予一个实体。它内部持有一个状态机，负责管理当前状态、处理状态转换，并驱动当前状态的 `Update` 和 `CheckTransitions` 方法。

## 与行为树的关系

FSM与行为树（Behavior Tree）协同工作，但职责不同：
- **FSM (本目录)**: 负责**战略层面**的决策。决定Boss当前应该用**哪一套战术**（例如，一阶段的战术组合 vs 二阶段的战术组合）。
- **行为树 (`Core/ECS/BehaviorTree`)**: 负责**战术层面**的决策。在FSM决定的某个特定阶段内，具体执行哪一个攻击、如何移动、如何组合技能。

简单来说，FSM是将军，决定大的战略方向；行为树是士兵，执行具体的战术动作。
