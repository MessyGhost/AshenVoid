# 行为树 (Behavior Tree) 目录

## 职责

本目录实现了一个行为树（BT），用于管理NPC的**战术层面、细节化**的行为逻辑。当FSM决定了Boss处于某个宏观阶段（如`Phase1State`）后，由行为树来具体控制这一阶段内的移动、攻击选择和技能组合。

行为树通过将复杂的行为分解为一系列简单的、可重用的节点，来构建出富有逻辑性的AI。

## 核心概念与文件

- **`BehaviorTreeNodes.cs`**: 定义了行为树的基本构建模块。
    - **`Node`**: 所有节点的基类，定义了 `Evaluate` 方法。
    - **`CompositeNode`**: 组合节点，可以有多个子节点。
        - **`SequenceNode` (顺序节点)**: 按顺序执行其子节点。一旦有子节点返回`Failure`或`Running`，则立即停止并返回该状态。只有所有子节点都返回`Success`，它才返回`Success`。类似于逻辑上的“与”（AND）。
        - **`SelectorNode` (选择节点)**: 按顺序执行其子节点。一旦有子节点返回`Success`或`Running`，则立即停止并返回该状态。只有所有子节点都返回`Failure`，它才返回`Failure`。类似于逻辑上的“或”（OR）。
    - **`ActionNode` (行动节点)**: 叶子节点，执行具体的操作（如一次攻击、一次移动），并返回执行结果。
    - **`WaitNode` (等待节点)**: 一个特殊的行动节点，用于在行为序列中插入等待时间。

- **`AIBehaviorFactory.cs`**: 一个工厂类，用于创建和组装具体的行为树。推荐将不同阶段或不同Boss的行为树创建逻辑都集中在这里，方便管理。

## 如何使用

1.  在 `AIBehaviorFactory` 中创建一个新的方法，用于构建你的行为树，例如 `CreateMyBossPhase1Tree()`。
2.  在该方法中，使用 `SequenceNode`, `SelectorNode`, `ActionNode` 等来组合你的AI逻辑。
3.  `ActionNode` 中的逻辑通常会与 `EcsWorld` 交互，获取实体组件并修改它们的数据，或者发布事件，从而驱动游戏世界发生变化。
4.  在Boss的某个 `State` 中（例如 `Phase1State`），调用 `AIBehaviorFactory` 来获取构建好的行为树，并在该 `State` 的 `Update` 方法中持续调用树的根节点的 `Evaluate` 方法。

通过这种方式，复杂的AI逻辑被清晰地组织在行为树中，而FSM则负责在合适的时机切换使用哪一棵行为树。
